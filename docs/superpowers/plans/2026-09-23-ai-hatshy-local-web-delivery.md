# AI Hatshy — Local Web Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for approved implementation packages. Follow project CAO/taskboard rules. This document plans capabilities; it does not authorize paid API requests or sending meeting data to external services during development.

**Goal:** Проверяющий клонирует Git-репозиторий на Windows/macOS/Linux, запускает приложение локально, открывает браузер, устанавливает модели кнопкой и обрабатывает свою запись. Выбор LLM: встроенная локальная модель, локальная Ollama или явно включённый OpenAI API с собственным ключом.

**Architecture:** Общий веб-клиент и локальный backend с AI-worker. Базовый путь воспроизведения — Docker Compose с CPU-профилем, отдельные проверенные профили ускорения и нативный runtime для Apple Silicon. Все AI-запросы выполняются backend, а не браузером.

**Tech Stack:** Стек web-first редакции сохраняется: React/TypeScript, Rust HTTP API/core, SQLite, whisper.cpp, локальная диаризация, llama-helper; добавляются адаптеры Ollama/OpenAI, серверный менеджер моделей, multi-arch сборка и сценарии установки. Docker — инструмент поставки, а не обязательный способ запуска ускоренных моделей на Mac.

---

## 1. Приоритеты

1. Воспроизводимый локальный запуск из Git на Windows и Apple Silicon; Linux — отдельный проверяемый целевой профиль.
2. Полный сценарий через браузер, без зависимости от компьютера автора или установленного Mac-приложения.
3. Скачивание и выбор моделей из UI, без ручного редактирования исходников.
4. Полностью локальный режим, работающий без API-ключей после загрузки моделей.
5. Ollama и OpenAI как дополнительные варианты сводки/поручений.
6. Сетевой сервер для организации и Mac DMG не блокируют сдачу локальной веб-версии.

Это уточнение заменяет предположение, что проверяющие обязательно подключаются к Mac автора. Каждый экземпляр может работать независимо на машине проверяющего.

## 2. Как сдаётся проект

В README первой секцией будет Quick start. Планируемый контракт запуска (команда заработает после реализации Compose):

```sh
git clone https://github.com/BAITC-Hacks/hack-c9414062-smaguloveka.git
cd hack-c9414062-smaguloveka
docker compose up --build -d
```

Далее — открыть `http://localhost:3000`. Предварительные зависимости: Git и работающий Docker с Compose; для Docker Desktop на Windows — поддерживаемая конфигурация WSL2/виртуализации по инструкции Docker. Rust/Node/Python на машине проверяющего не нужны при этом способе запуска.

- В репозитории есть Dockerfile, compose.yaml, lockfiles, healthchecks, примеры без секретов и документация остановки/повторного запуска.
- UI запускается без скачанных весов и ведёт пользователя к установке моделей.
- Модели, база, записи и конфигурация лежат в persistent volumes вне слоёв образа. Перезапуск/пересборка не скачивает веса заново и не удаляет встречи.
- По умолчанию порт доступен на loopback, а не всей локальной сети. Серверная авторизация/защита запросов сохраняется; первоначальная настройка владельца не требует почты или облачного аккаунта.
- Интернет нужен для первого получения зависимостей/моделей; для закрытого контура документируется перенос готовых образов и модельного пакета.
- Веса и секреты не коммитятся в Git. Manifest фиксирует версию, источник, лицензию, размер и контрольную сумму модели.
- Windows и Linux CPU-profile собирается под amd64, Apple Silicon CPU-container — под arm64. Возможность сборки/работы подтверждается отдельно, без неявного предположения об эмуляции x86.

## 3. Мастер первого запуска

### Шаг 1: диагностика

Показать реальную ОС/архитектуру backend, доступную ему память, место для моделей и используемый CPU/GPU runtime. В Docker отдельно обозначать лимит памяти контейнера; браузер не считается надёжным источником RAM/GPU сервера.

### Шаг 2: распознавание и голоса

Карточки проверенных ASR/диаризационных моделей: назначение, языки, размер, требования, лицензия, состояние и кнопка «Скачать». Отдельно указываются экспериментальные модели, для которых качество ещё не подтверждено.

### Шаг 3: сводка и поручения

Выбор «Встроенная локальная модель», «Ollama», «OpenAI API». По умолчанию выбран локальный вариант и строгая локальная политика. Облачный вариант требует явного выхода из этой политики.

### Шаг 4: проверка готовности

Короткая проверка runtime/моделей, вывод выбранных провайдеров по этапам, затем запись/импорт или просмотр обозначенной демо-встречи. Проверка облачной генерации использует синтетический текст и явно обозначается как API-запрос, который может тарифицироваться.

## 4. Менеджер моделей

В UI: каталог, «Скачать», прогресс/размер, отмена, повтор, проверка целостности, «Выбрать», установленные версии и удаление неиспользуемых весов.

- Загрузка выполняется backend на компьютер, ГДЕ ЗАПУЩЕН BACKEND. В основном локальном сценарии это компьютер проверяющего; при сетевом сервере — сервер, не компьютер посетителя браузера.
- Встроенный каталог указывает формат, runtime и совместимость. GGUF LLM и веса Whisper не считаются взаимозаменяемыми файлами.
- Обрыв не оставляет модель в состоянии «Готова»: временный файл, проверка checksum и атомарная публикация после окончания.
- Продолжение скачивания используется, когда источник поддерживает Range; иначе UI честно показывает повтор с начала.
- Не допускаются две параллельные загрузки одной версии. Удаление используемой модели требует сначала завершить/отменить связанные задачи.
- Повторный вход в UI восстанавливает реальное состояние серверной загрузки; закрытие вкладки не отменяет её молча.
- Поддерживается импорт подготовленного локального модельного пакета. Для gated моделей показываются реальные требования доступа/лицензии, без обещания скачивания без аккаунта.
- Веса не скачиваются заново при каждой обработке и не загружаются все одновременно в RAM.

## 5. Провайдеры LLM

| Провайдер | Настройки | Где обработка |
|---|---|---|
| Встроенная модель | Проверенный GGUF, параметры контекста, выбранный профиль ресурсов | Локальный runtime backend |
| Ollama | Адрес, проверка сервиса, список установленных моделей, pull модели, выбор | На настроенном Ollama-host |
| OpenAI API | Собственный API key, совместимая доступная модель, тест соединения/генерации | Внешний сервис OpenAI |

Единый внутренний контракт возвращает структурированные поручения и саммари, учитывает лимиты контекста, признак усечения и ошибки. На всех провайдерах применяются одинаковые правила доказательств/сроков и валидация. Выбор провайдера не является гарантией качества произвольной модели.

Выбранные provider/model/version сохраняются вместе с результатом. Повторная генерация создаёт новую версию и не стирает подтверждённые ручные исправления.

### Ollama

- Если Ollama уже установлена, пользователь подключает её без повторной загрузки имеющихся моделей.
- Если сервиса нет, UI сообщает это; установка LLM через pull не устанавливает сам Ollama runtime. Предусматривается опциональный Compose-сервис Ollama для CPU-пути или отдельная нативная установка.
- Backend читает список моделей и выполняет pull с прогрессом; нужные части уже существуют в Memora `src-tauri/src/ollama/`.
- Адрес localhost внутри Docker указывает на контейнер. Настройка учитывает подключение к хосту/Compose-сервису; на Windows/Mac и Linux проверяются соответствующие адреса. Пользователь видит адрес назначения и результат диагностики.
- Строгий локальный режим допускает только локально исполняемые модели на разрешённом host. Само название Ollama не доказывает отсутствие cloud inference; удалённые/cloud варианты не используются как скрытый fallback.
- Docker/нативные Ollama модели хранятся в собственном persistent каталоге сервиса, а UI не показывает их как встроенные GGUF-файлы приложения.

### OpenAI

- Пользователь вводит собственный ключ через настройки своего экземпляра. Сохранённый ключ не возвращается frontend, не хранится в localStorage и не попадает в логи/экспорт/репозиторий.
- Запросы идут через backend. Секрет хранится в серверном SecretStore, ключ шифрования/защита хранилища отделены от базы.
- Приложение различает проверку доступа, наличие модели и успешную генерацию; список `/models` сам по себе не доказывает совместимость или наличие квоты.
- В интерфейсе виден факт передачи текста в OpenAI, выбранная модель и ошибки доступа/лимитов. В этой функции отправляется текст, а не аудио.
- При ошибке локальной модели запрещено автоматически переключаться на OpenAI. Уже поставленная задача сохраняет своего провайдера.
- Ключи не запрашиваются в чате. Для реализации/проверки живого API действуют инструкции OpenAI platform API key skill.

Официальное требование server-side хранения ключей: https://developers.openai.com/api/reference/overview/#authentication.

## 6. Два режима и соответствие ТЗ

**Закрытый контур / конкурсный режим — по умолчанию:** ASR и диаризация локально; LLM встроенная или локальная Ollama; внешняя AI-обработка блокируется backend, а не только скрывается в UI. СЭД ограничены разрешёнными назначениями. Проверка выполняется с отключённым интернетом после подготовки моделей.

**Режим с внешним AI — опциональный:** собственный OpenAI key и явный выбор пользователя для разрешённых данных. Транскрипт уходит наружу, поэтому такой запуск НЕ соответствует исходному ограничению кейса, даже если само приложение открыто на localhost.

Наличие OpenAI как дополнительной возможности не должно делать локальный путь неработоспособным или обязательным к обходу. В конкурсном README демонстрация проводится локально. Допустимость самого наличия опции в сдаваемой сборке определяется организаторами; при необходимости конкурсная конфигурация исключает её.

## 7. Производительность и платформы

- Базовый переносимый профиль использует CPU и короткую тестовую запись. Быстрая работа больших моделей на любом ноутбуке не обещается.
- Рекомендации RAM/диска публикуются после замеров, отдельно по профилям; качество компактной модели на казахском/MIX не приравнивается к более крупной автоматически.
- Для Apple Silicon нужен нативный путь к Metal: отдельный проверенный model runtime/локальный запуск приложения. Он может обслуживать тот же веб-интерфейс; Tauri для этого не обязателен.
- Для Windows/Linux с NVIDIA предоставляется отдельный GPU-профиль с документированными драйверами/runtime. CPU-путь не должен требовать CUDA.
- Нативный Ollama на Apple Silicon — рекомендованный путь для его ускорения в соответствующем руководстве Docker: https://docs.docker.com/guides/genai-pdf-bot/.
- Автовыбор ускорения подтверждается реальным запуском; при отсутствии GPU честно показывается CPU.

## 9. Приёмка сдачи

- [ ] Чистый clone на Windows: базовая команда запускает UI без ключей автора и dev-toolchain на хосте.
- [ ] Чистый clone на Apple Silicon и Linux: проверен соответствующий профиль и архитектура образа.
- [ ] Без моделей пользователь может открыть интерфейс, увидеть диагностику и установить нужные веса кнопкой.
- [ ] Скачивание переживает перезагрузку страницы, повреждённый файл не становится готовой моделью.
- [ ] Модели и встречи остаются после stop/start и пересборки приложения.
- [ ] Полностью локальный путь проходит новую запись до PDF/DOCX с отключённым интернетом.
- [ ] Отдельно проверен Ollama: список, pull, выбор, недоступный сервис, неверная модель, ограничения контекста.
- [ ] OpenAI-путь сначала проверен контрактными тестами; реальный синтетический запрос только с разрешённым доступом. Невалидный ключ/квота дают понятную ошибку, а не фиктивный успешный результат.
- [ ] Конкурсная политика запрещает внешние AI-запросы, включая обход через настройки/endpoint; автоматического fallback в облако нет.
- [ ] На каждой проверенной платформе опубликованы фактические конфигурация, длительность записи, время обработки, память и замечания к качеству.
- [ ] Короткое видео показывает именно свежий запуск и реальную обработку; подготовленное демо помечено отдельно.

## 10. Обновлённый порядок работ

Сначала — проверяемая CPU-поставка из Git, UI без моделей, менеджер загрузки и локальный сквозной сценарий. Далее — Ollama, опциональный OpenAI, ускорение и проверки на других ОС. Интеграции СЭД и работа с поручениями сохраняют прежние требования. Организационный сетевой режим, desktop DMG и боты развиваются после того, как основной проверяющий способен самостоятельно воспроизвести проект.
