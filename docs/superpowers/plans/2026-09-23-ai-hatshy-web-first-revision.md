# AI Hatshy Web-first Implementation Plan

> **Уточнение поставки пользователем:** основной способ проверки — каждый проверяющий разворачивает приложение из Git НА СВОЁМ компьютере Windows/macOS/Linux и открывает localhost; скачивание моделей и выбор встроенной LLM/Ollama/OpenAI доступны в UI. [Актуальные требования к сдаче и провайдерам](2026-09-23-ai-hatshy-local-web-delivery.md) имеют приоритет в вопросах установки, первого запуска и облачного режима. Общий сервер организации остаётся дополнительным режимом.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for approved implementation packages. Follow the project CAO/taskboard workflow; do not treat this plan as permission to expose the machine to a network or publish customer data.

**Goal:** Основной продукт — веб-приложение для пользователей Windows/macOS/Linux; дополнительная поставка — macOS-приложение с тем же интерфейсом и локальной записью. AI выполняется на выбранном компьютере или сервере внутри контура заказчика.

**Architecture:** Общий React-интерфейс обращается к HTTP API. Rust-ядро выделяется из Memora в независимую от Tauri библиотеку, сервер предоставляет авторизацию, API, обработку и доставку. Tauri служит дополнительной оболочкой и адаптером записи; существующие команды invoke не становятся HTTP API автоматически.

**Tech Stack:** React/TypeScript, статическая сборка Next.js для переиспользования Memora, Tailwind/Radix; Rust + Axum/Tokio, SQLx/SQLite для односерверного пилота; whisper.cpp/Metal на Mac и проверенный backend ускорения на сервере заказчика; llama-helper/llama.cpp; HTTP API + SSE для прогресса; Tauri 2 для Mac. Конкретные версии, движок диаризации и веса фиксируются после измерений.

## 1. Приоритет и связь с предыдущим планом

Этот документ заменяет desktop-first архитектуру предыдущего плана. Функциональные требования к AI, поручениям, экспорту, множественным СЭД, ботам и их ограничениям сохраняются. Календарь и плановые напоминания остаются следующим этапом.

Первая приёмка выполняется целиком в обычном браузере без Tauri и без установленных на компьютере пользователя моделей. macOS-сборка не должна быть обязательна для основного сценария.

## 2. Два способа поставки

### Веб — основной

- На твоём M1 Pro запускается сервер приложения и AI-worker. Сам пользователь открывает localhost.
- Для показа с другого компьютера включается отдельный сетевой режим с HTTPS и авторизацией, в разрешённой сети/VPN.
- Windows/macOS/Linux пользователям нужен поддерживаемый браузер, а не Mac или локальная GPU.
- Запись или файл передаются на сервер; транскрипция, модели, база и СЭД-интеграции работают там.
- Для заказчика сервер переносится на его выделенную машину. Предусмотрены нативный запуск на Apple Silicon и отдельный проверенный Linux-пакет/контейнерная поставка.
- Для демонстрации на твоём Mac он должен оставаться включённым и доступным. Размещение одного frontend на публичном хостинге не заменяет AI-server и не разрешает передачу туда записей.

### macOS — дополнительный

- Tauri использует общий интерфейс и API-клиент, добавляя нативный захват микрофона/системного звука.
- Автономный режим запускает комплектный локальный сервер на loopback и модели из локального каталога.
- Серверный режим подключается к разрешённому серверу организации; пользователь явно видит место обработки.
- Базы автономного и серверного режимов отдельные. Автоматической синхронизации между ними в первой версии нет.
- Нативные операции доступны только оболочке; основная бизнес-логика не зависит от Tauri AppHandle, dialog или frontend invoke.
- Для loopback API предусматриваются проверка Origin и секрет сессии/равноценная защита; localhost не считается разрешением любому сайту вызывать привилегированные методы.

## 3. Общая схема

```text
Браузер Windows / macOS / Linux        Mac-приложение Tauri
                  \                    /      + нативная запись
                    Общий HTTP API
                    Авторизация / права
                    Rust application core
                    /         |          \
             SQLite       AI-worker     Очередь доставки
                |        ASR/голоса/LLM       |
          Файлы записей                 Разрешённые СЭД
```

Frontend собирается как статический клиент, без зависимости от Next.js Server Actions. Бизнес-операции идут через Rust API. Статическая сборка совместима с подходом Tauri: https://v2.tauri.app/start/frontend/nextjs/.

## 4. Изменения по сравнению с Memora

| Что переиспользуем | Какая адаптация нужна |
|---|---|
| Whisper, llama-helper, нормализация AI-ответов | Отделить от AppHandle, передавать пути/конфиг и события через интерфейсы |
| SQLite-репозитории | Добавить пользователей, права доступа, версии и принадлежность объектов |
| Цитаты, поручения, сроки | Общие серверные операции с проверкой прав |
| PDF/DOCX | Генерация байтов на сервере и скачивание по авторизованному запросу вместо нативного диалога |
| Коннекторы/очередь СЭД | Выполнять на сервере, хранить credentials на стороне сервера |
| Управление моделями | Только администратор сервера; обычные пользователи видят готовность обработки |
| Запись системного звука | Оставить нативной возможностью Mac, отдельно реализовать доступные браузерные источники |
| UI | Перенести дизайн AI Hatshy, использовать API-клиент вместо прямых invoke в компонентах |

На Mac секреты могут использовать Keychain; серверу Linux нужен отдельный SecretStore. При переносе нельзя считать Keychain кроссплатформенным решением: серверный вариант использует защищённое хранилище с ключом вне БД, политика резервного копирования учитывает восстановление ключей.

## 5. Запись в браузере

1. Загрузка поддерживаемого аудио/видео — базовый общий путь для всех целевых платформ.
2. Запись микрофона — MediaDevices/MediaRecorder, проверка доступности и формата в выбранном браузере.
3. Запись аудио вкладки/экрана — только для реально поддерживаемой комбинации ОС/браузера/источника; проверяем наличие audio track и не обещаем звук по одному факту разрешения screen sharing.
4. Нативная запись в Mac-клиенте и проверенные meeting bots остаются альтернативными источниками.

Микрофон требует secure context: localhost подходит на том же компьютере, для сетевого доступа нужен корректный HTTPS. Источники и поддержка аудио getDisplayMedia различаются: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia и https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia.

Запись передаётся серверу частями с порядковыми номерами и подтверждением приёма. Повтор части не дублирует звук. При сетевом разрыве показываем несохранённый объём; локальный буфер ограничен квотой браузера. Полностью принятая сервером запись обрабатывается после закрытия вкладки, но продолжение самой браузерной записи после закрытия вкладки не обещается.

## 6. Многопользовательская работа

Сетевой режим требует реальной авторизации, а не переключателя роли из макета. Пилот рассчитан на одну организацию на установку, без публичной регистрации.

- Администратор: пользователи, доступы, модели, подключения СЭД, серверные настройки.
- Секретарь: назначенные/свои встречи, загрузка/запись, исправления, подтверждение и разрешённая отправка.
- Руководитель/исполнитель: только доступные ему встречи/поручения и разрешённые изменения статуса.
- Права проверяет API для каждой встречи, аудиофайла, цитаты, поручения, экспорта и события прогресса.
- Учётные записи создаёт администратор. Локальная аутентификация использует хеширование паролей и защищённые сессии; SSO не входит в первую поставку.
- Изменения протокола используют номер версии, чтобы правки двух пользователей не перетирались молча.
- Файлы хранятся вне публичного web-каталога, скачиваются через проверку доступа.

На M1 Pro одновременно могут быть несколько пользователей интерфейса, но AI-обработка по умолчанию последовательная. Фактическое число комфортных пользователей определяется нагрузочным тестом; оно не равно числу одновременных AI-задач.

## 7. Предлагаемая структура

```text
apps/web/                 общий интерфейс по дизайну AI Hatshy
apps/desktop/             Tauri, разрешения ОС, нативная запись
crates/core/              модели предметной области и use cases
crates/server/            HTTP API, сессии, права, статические файлы, SSE
crates/storage/           SQLx, миграции, доступ к файлам
crates/processing/        очередь, checkpoints, ресурсы моделей
crates/integrations/      подключения, adapters, mapping, outbox
packages/api-client/      типизированные запросы и события frontend
evaluation/               RU/KK/MIX разметка, качество, производительность
deploy/macos/             нативный сервер и пакет моделей
deploy/linux/             серверная поставка, volumes, HTTPS-конфиг
docs/                     установка, архитектура, demo, API, ограничения
```

Один односерверный пилот использует SQLite с миграциями, транзакциями и тестами конкурентной записи. База не размещается на общем сетевом диске. PostgreSQL рассматривается при переходе к нескольким серверным процессам/узлам и иной нагрузке; автоматическая бесплатная миграция не предполагается.

## 8. Новый порядок реализации

- [ ] **A. AI-эксперимент:** модели, M1 Pro/16 ГБ, RU/KK/MIX, голоса, реальная память/время; сохраняется из предыдущего плана.
- [ ] **B. Выделение core + API:** изолировать нужные модули Memora, реализовать сервер, хранение, обработку и события независимо от Tauri.
- [ ] **C. Авторизация и загрузка:** локальный администратор, роли/доступы, надёжная загрузка файлов/частей аудио, ограничения размера и состояния ошибок.
- [ ] **D. Основной веб:** дизайн AI Hatshy, встречи, транскрипт, плеер, поручения, версии и экспорт через API.
- [ ] **E. Реальные интеграции:** несколько СЭД, mapping, server-side secrets, outbox и тестовый стенд по предыдущему плану.
- [ ] **F. Сетевая поставка:** HTTPS внутри контура, установка на сервер, резервные копии, восстановление, безопасный доступ другого компьютера.
- [ ] **G. Mac-сборка:** общий UI + нативная запись, автономный серверный процесс, DMG и отдельный профиль.
- [ ] **H. Meeting bots:** платформенные адаптеры по прежнему плану и реальным условиям доступа; основной web-upload сценарий от них не зависит.

Календарь и напоминания остаются отложенными. Мобильный браузер получает адаптивный просмотр/работу в пределах проверенных функций; отдельное нативное мобильное приложение не заявляется. Фоновая запись на телефоне не обещается без проверки ограничений ОС.

## 9. Критерии готовности веб-версии

1. Пользователь на Windows открывает HTTPS-адрес и входит без установки клиентских моделей.
2. Загружает ранее не обработанную запись, получает реальный прогресс и результат.
3. После загрузки закрывает вкладку; сервер завершает задачу, результат доступен при следующем входе.
4. Видит только разрешённые встречи/файлы; попытки доступа к чужим ID отклоняются сервером.
5. Прослушивает источник поручения, исправляет данные, подтверждает версию.
6. Скачивает реальные PDF/DOCX и отправляет результат в несколько разрешённых СЭД.
7. Два пользователя не перезаписывают изменения друг друга незаметно.
8. При перезапуске сервера данные и очередь восстанавливаются; частичная загрузка не становится готовой встречей.
9. RU/KK/MIX качество подтверждено отдельно; выбранные браузеры проверены по функциям загрузки, микрофона, плеера и экспорта.
10. После установки моделей основной конвейер не отправляет данные во внешние AI API. Локальная сеть/VPN не считается внешним AI-облаком, но сервер должен быть внутри разрешённого контура.

## 10. Что не меняется в покрытии ТЗ

Распознавание, диаризация, поручения, саммари, PDF/DOCX и интеграции выполняются на backend и не зависят от ОС клиента. Ограничения ботов Teams/Meet/Zoom остаются. Автоматические напоминания пока не закрывают второй сценарий ТЗ. Переход на веб добавляет необходимую серверную работу: HTTP API, аутентификацию, права, сетевую загрузку, HTTPS и эксплуатацию; это реальная адаптация, а не публикация текущей Tauri-сборки как сайта.
