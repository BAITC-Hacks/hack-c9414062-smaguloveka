# MCP-сервер AI Hatshy

MCP-сервер позволяет ИИ-ассистентам (Claude Code, Claude Desktop и любым клиентам, поддерживающим
Model Context Protocol) работать с данными AI Hatshy: смотреть совещания, сводки и стенограммы, искать по записям,
вести поручения (статус, срок, ответственный), отправлять напоминания, загружать новые записи и выгружать протоколы.

Примеры запросов к ассистенту:

- «Какие поручения просрочены и у кого?»
- «Что решили на планёрке по бюджету? Кто отвечает за обоснование?»
- «Найди в стенограммах, где обсуждали сроки поставки»
- «Отметь поручение #18 выполненным»
- «Загрузи ~/Records/meeting.mp3 как „Совещание по закупкам“ и сообщи, когда будет готово»
- «Выгрузи обезличенный протокол совещания #3 в PDF»

## Как это устроено

- Файл: `app/mcp_server.py`, транспорт **stdio** (клиент сам запускает процесс).
- Реализован на официальном Python SDK (`mcp`, класс FastMCP / MCPServer).
- Сервер — тонкая прослойка над HTTP API AI Hatshy: **веб-сервер должен быть запущен**
  (`.venv/bin/python -m uvicorn app.main:app --port 8000`). Если он не запущен, инструменты вернут понятную ошибку
  с подсказкой, как его запустить.
- **Закрытый контур.** MCP-сервер обращается только к локальному API (по умолчанию `http://localhost:8000`).
  Нелокальные адреса заблокированы, а системные прокси игнорируются. Аудио и данные никуда не передаются.
  Учтите: текст, который вернул инструмент, получает ИИ-модель клиента. Если клиент работает с облачной моделью
  (например, Claude), фрагменты протоколов попадут к ней. Для полностью закрытого контура подключайте MCP-сервер
  к клиенту с локальной моделью.
- Все описания инструментов и ответы — на русском языке. Ответы компактные: длинные тексты обрезаются,
  длинная стенограмма выдаётся порциями.

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HATSHY_URL` | `http://localhost:8000` | Адрес API AI Hatshy |
| `HATSHY_ALLOW_REMOTE` | не задана | `1` разрешает нелокальный адрес (например, сервер в локальной сети) |

## Инструменты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `list_meetings` | — | Список совещаний: id, название, дата, длительность, статус, языки, число поручений и неподтверждённых |
| `get_meeting` | `meeting_id: int`, `include_transcript: bool = false`, `transcript_from: int = 0` | Сводка, решения, темы, ключевые цифры, говорящие (роль, доля речи), поручения (ответственный, срок, статус, приоритет, направление, цитата с таймкодом) и подробная сводка, если она сформирована. Стенограмма в формате `[чч:мм:сс] Имя (язык): текст` выводится только при `include_transcript=true`, порциями примерно по 24 тыс. символов. Следующую порцию запрашивайте с `transcript_from` |
| `list_tasks` | `status: all\|work\|done\|overdue = all`, `owner: str?`, `meeting_id: int?`, `due_before: YYYY-MM-DD?` | Поручения из всех совещаний. `owner` ищет по части имени без учёта регистра, `due_before` включает указанную дату. Просроченным считается поручение в работе со сроком раньше «сегодня» по серверу |
| `update_task` | `task_id: int`, `status: work\|done?`, `confirmed: bool?`, `due: YYYY-MM-DD?` (пустая строка снимает срок), `owner: str?`, `title: str?`, `priority: high\|mid\|low?` | Меняет поручение. Передаются только изменяемые поля, каждое изменение пишется в историю |
| `remind_task` | `task_id: int` | Сразу отправляет напоминание ответственному: уведомление в приложении и письмо в локальный outbox |
| `search_transcripts` | `query: str`, `limit: int = 20` (1–100) | Ищет по стенограммам всех совещаний без учёта регистра. Для каждой находки: совещание, таймкод, говорящий, фрагмент реплики |
| `upload_meeting` | `file_path: str`, `title: str = ""`, `date: YYYY-MM-DD = ""`, `participants: str = ""` (через запятую) | Загружает локальный аудио- или видеофайл и запускает обработку. Возвращает id совещания |
| `get_processing_status` | `meeting_id: int` | Показывает ход обработки: статус, процент, текущий этап и список этапов |
| `export_protocol` | `meeting_id: int`, `fmt: docx\|pdf = docx`, `anonymize: bool = false`, `output_dir: str = ~/Downloads` | Формирует протокол (DOCX или PDF) и сохраняет его на диск. Возвращает путь к файлу, существующие файлы не перезаписываются |

Инструменты только для чтения помечены подсказкой `readOnlyHint`, изменяющие (`update_task`, `remind_task`,
`upload_meeting`, `export_protocol`) — нет. По этой подсказке клиент может, например, спрашивать подтверждение
только перед изменяющими действиями. Кроме того, в инструкциях сервера ассистенту сказано выполнять изменения
только по явной просьбе пользователя.

Дополнительно:

- ресурс `hatshy://meetings` — список совещаний текстом;
- шаблон запроса `overdue_digest` — сводка для руководителя по просроченным и горящим поручениям.

## Подключение

Для запуска удобнее всего обёртка `scripts/mcp.sh`. Она переходит в корень проекта и запускает
`.venv/bin/python -m app.mcp_server`. Сервер нужно запускать из корня проекта, иначе Python не найдёт пакет
`app`, а обёртка делает это сама, поэтому рабочую папку клиента настраивать не нужно.

Ниже `/ABS/PATH/ai-hatshy` — абсолютный путь к проекту. Узнать его можно командой `pwd` в корне проекта.

Сначала запустите веб-сервер AI Hatshy:

```bash
cd /ABS/PATH/ai-hatshy
.venv/bin/python -m uvicorn app.main:app --port 8000
```

### Claude Code

```bash
claude mcp add ai-hatshy -- /ABS/PATH/ai-hatshy/scripts/mcp.sh
```

- Чтобы сервер был доступен во всех проектах, добавьте `--scope user`:
  `claude mcp add --scope user ai-hatshy -- /ABS/PATH/ai-hatshy/scripts/mcp.sh`.
- Если API работает на другом порту, передайте адрес:
  `claude mcp add ai-hatshy -e HATSHY_URL=http://localhost:8001 -- /ABS/PATH/ai-hatshy/scripts/mcp.sh`.
- Проверка: `claude mcp list` (статус `ai-hatshy … ✓ Connected`) или команда `/mcp` внутри Claude Code.

Можно запускать и без обёртки, но тогда Claude Code нужно открывать из корня проекта: stdio-сервер
запускается в папке, откуда запущен `claude`.

```bash
cd /ABS/PATH/ai-hatshy
claude mcp add ai-hatshy -- /ABS/PATH/ai-hatshy/.venv/bin/python -m app.mcp_server
```

### Claude Desktop

Откройте файл `claude_desktop_config.json`: в Claude Desktop выберите Settings → Developer → Edit Config.
На macOS файл лежит в `~/Library/Application Support/Claude/claude_desktop_config.json`.
Добавьте в него:

```json
{
  "mcpServers": {
    "ai-hatshy": {
      "command": "/ABS/PATH/ai-hatshy/scripts/mcp.sh",
      "env": { "HATSHY_URL": "http://localhost:8000" }
    }
  }
}
```

После этого перезапустите Claude Desktop. Инструменты AI Hatshy появятся в меню инструментов (значок молотка
или «+» → Connectors).

### Другие MCP-клиенты

Подойдёт любой клиент с поддержкой stdio: укажите в нём команду `/ABS/PATH/ai-hatshy/scripts/mcp.sh`.
Для отладки используйте MCP Inspector:

```bash
npx @modelcontextprotocol/inspector /ABS/PATH/ai-hatshy/scripts/mcp.sh
```

## Частые проблемы

| Симптом | Решение |
|---|---|
| «Сервер AI Hatshy не запущен или недоступен…» | Запустите `uvicorn app.main:app --port 8000` или проверьте `HATSHY_URL` |
| «Адрес … не локальный» | Сработала защита закрытого контура. Для сервера в локальной сети задайте `HATSHY_ALLOW_REMOTE=1` |
| `ModuleNotFoundError: app` | Сервер запущен не из корня проекта. Используйте `scripts/mcp.sh` |
| `ModuleNotFoundError: mcp` | Установите SDK: `uv pip install --python .venv/bin/python "mcp>=1.2"` |
