# AI Hatshy — локальный ИИ-секретарь совещаний

Решение кейса HackAlem AI «Система автопротоколирования совещаний с фиксацией поручений».

AI Hatshy (от каз. «хатшы» — секретарь) превращает запись совещания в протокол. Он распознаёт речь на русском, казахском и шала-казахском, разделяет говорящих и определяет их имена. Из разговора он выделяет поручения: кто отвечает, что сделать и к какому сроку. Дальше формирует саммари, экспортирует протокол в PDF и DOCX, ведёт статусы поручений и напоминает о сроках.

**По умолчанию все модели работают локально.** Аудио и текст совещания не отправляются во внешние API. Распознавание — ONNX на CPU, LLM — в Ollama на той же машине. Внешний OpenAI-совместимый API можно включить в настройках (см. «Выбор LLM»); аудио в любом случае остаётся на сервере.

## Что реализовано

| Требование кейса | Как реализовано | Где в коде |
|---|---|---|
| 1. Распознавание речи | GigaAM-Multilingual large CTC (int8 ONNX), распознаёт каждую реплику после диаризации | `app/pipeline/asr.py` |
| 2–4. Русский, казахский, шала-казахский | Одна модель на RU и KZ с общим словарём: без языкового токена, поэтому смешанная речь распознаётся без переключения. Язык реплики (`RU` / `KZ` / `RU+KZ`) определяется по казахским буквам и служебным словам | `app/pipeline/asr.py`, `app/pipeline/text.py` |
| 5. Поручения с ответственным и сроком | Локальная LLM (gemma4 в Ollama) извлекает поручения по JSON-схеме. Затем детерминированная проверка: цитата должна дословно найтись в транскрипте, срок разбирается правилами от даты совещания («до пятницы», «к среде», «жұмаға дейін» → дата) | `app/pipeline/llm/*`, `app/pipeline/protocol.py` |
| 6. Диаризация и привязка поручения к человеку | Детектор речи Silero VAD → голосовые эмбеддинги NeMo TitaNet-small (sherpa-onnx) → агломеративная кластеризация (число голосов подбирается автоматически, мелкие кластеры поглощаются) → поиск смены говорящего внутри длинных фрагментов. Имена говорящих определяются по обращениям («Гульмира Сериковна, вам слово» → следующая реплика принадлежит ей), при ошибке их можно переименовать в интерфейсе | `app/pipeline/diarize.py`, `app/pipeline/llm/speaker_names.py` |
| 7. Экспорт протокола в PDF/DOCX | Макет эталонных протоколов организаторов: тема, краткое содержание, решения, таблица «Поручение / Ответственный / Срок», стенограмма с таймкодами, участники, подписи. Есть анонимизация ФИО | `app/export/*` |
| Сценарий 1: уведомление о записи | Переключатель «Уведомить участников о записи». При старте записи проигрывается объявление на казахском и русском (`app/static/consent.mp3`), отметка о согласии сохраняется в совещании | `web/index.html`, `app/main.py` |
| Сценарий 2: напоминания о сроках | Правила «за 3 дня», «в день срока», «ежедневно при просрочке», «эскалация куратору». Каналы: лента уведомлений и письма `.eml` в локальный `data/outbox/` | `app/reminders.py` |
| Краткая и подробная сводка | Вкладка «Краткая сводка»: краткое содержание, решения, повестка с таймкодами, ключевые цифры, доля речи. Вкладка «Подробная сводка»: отдельный отчёт LLM для тех, кто не был на встрече — разбор каждого вопроса, факты и цифры, решения, поручения, риски, открытые вопросы, позиции участников, следующие шаги | `app/pipeline/report.py` |
| Мастер первого запуска | Проверяет и скачивает модели распознавания (с прогрессом), помогает выбрать LLM: модель Ollama (с загрузкой через Ollama) или OpenAI API; открывается снова из «Настроек» | `app/setup.py` |
| Доп.: дашборд статусов | «В работе / Просрочено / Выполнено», исполнительская дисциплина, сроки на две недели, нагрузка по ответственным, доска и список с фильтрами | `web/index.html` |
| Доп.: рассылка выдержек | Каждому ответственному формируется письмо с его поручениями и цитатами, письма пишутся в локальный outbox | `app/reminders.py` |
| Доп.: классификация поручений | Направление (финансы, охрана труда, закупки…) — от LLM. Срочность (высокая / средняя / низкая) считается по сроку | `app/pipeline/protocol.py` |
| Доп.: on-premise | Внешних сервисов во время работы нет. React и шрифты лежат в репозитории, страницы не обращаются к CDN | `app/static/` |

**Выбор LLM** («Настройки» → «ИИ для поручений и саммари»). По умолчанию — локальная Ollama (закрытый контур). Можно переключиться на OpenAI API или на свой OpenAI-совместимый сервер (например, vLLM в контуре заказчика): указываются адрес, ключ и модель, есть кнопка «Проверить подключение».
- При выборе OpenAI во внешний API уходит только текст транскрипта; аудио, распознавание и диаризация остаются локальными. Интерфейс предупреждает, что это выход за закрытый контур.
- Ключ хранится в локальной БД (`data/`, в `.gitignore`) или в переменной `OPENAI_API_KEY`. API отдаёт в браузер только маску ключа.
- Код: `app/llm_settings.py`, `_call_openai` в `app/pipeline/llm/extract.py`.

Есть и мобильная версия (`/m`): главная, запись с микрофона, поручения, уведомления. Она устанавливается на телефон как веб-приложение.

## Архитектура

```
Браузер (веб /  или мобильный /m) ── REST ──► FastAPI (app/main.py) ──► SQLite (data/hatshy.db)
   │  запись: MediaRecorder, куски по 4 с                  │
   │  (микрофон или звук конференции через BlackHole)      ▼
   │                                              Очередь, по одной задаче (app/pipeline/runner.py)
   │                                                        │
   │   1. ffmpeg → 16 кГц моно
   │   2. Диаризация: Silero VAD → TitaNet-эмбеддинги → кластеризация (число голосов подбирается автоматически)
   │   3. ASR по каждой реплике: GigaAM-Multilingual (RU+KZ), регистр имён, тег языка реплики
   │   4. LLM (по умолчанию gemma4 в Ollama; или OpenAI-совместимый API): участники, поручения, саммари — JSON по схеме
   │   5. Проверка без LLM:
   │        • имена говорящих по обращениям
   │        • цитата поручения обязана найтись в транскрипте
   │        • сроки — детерминированный резолвер
   │        • срочность и направление
   │        • уверенность; «требует проверки», если цитата или срок не подтвердились
   │   6. Протокол → подробная сводка (второй вызов LLM) → напоминания (app/reminders.py) → экспорт PDF/DOCX
```

LLM здесь не последнее звено. Её ответ проверяют инструменты: цитата сверяется с транскриптом, срок пересчитывается резолвером, имя сверяется с обращениями. Поручение, которое не прошло проверку, получает низкую уверенность и помечается «требует проверки». Секретарь подтверждает поручения в интерфейсе, и это записывается в историю поручения.

## Стек

- **Backend:** Python 3.12, FastAPI, SQLite, ffmpeg.
- **ASR:** [GigaAM-Multilingual large CTC](https://huggingface.co/istupakov/gigaam-multilingual-large-ctc-onnx) (лицензия MIT, int8 ONNX, ~560 МБ) через `onnx-asr`.
- **Диаризация:** `sherpa-onnx`: Silero VAD (2 МБ) и NeMo TitaNet-small (38 МБ); кластеризация и поиск смены говорящего написаны в проекте.
- **LLM:** gemma4 8B (Q4_K_M) в Ollama, вызов только на `localhost:11434`.
- **Экспорт:** `python-docx`; `fpdf2` со шрифтом Montserrat (OFL, поддерживает казахские буквы ә ғ қ ң ө ұ ү һ і).
- **Frontend:** по дизайн-макету «AI Hatshy». Шаблоны на dc-runtime (`app/static/support.js`), React 18 UMD и шрифты IBM Plex лежат в `app/static/`.

## Установка и запуск

Нужно: macOS или Linux, Python 3.12, [uv](https://docs.astral.sh/uv/), ffmpeg, [Ollama](https://ollama.com). Проверено на MacBook Pro M1 Pro, 16 ГБ.

```bash
# 1. Зависимости
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r pyproject.toml

# 2. Модели (~0.6 ГБ, один раз; дальше работа без сети).
#    Можно пропустить — при первом открытии их скачает «Мастер настройки» в интерфейсе.
./scripts/download_models.sh

# 3. LLM (~9.6 ГБ)
ollama pull gemma4

# 4. Сервер
.venv/bin/python -m uvicorn app.main:app --port 8000
```

После запуска откройте http://localhost:8000 (веб) или http://localhost:8000/m (мобильная версия).

Настройки через переменные окружения (необязательно, см. `.env.example`): `LLM_MODEL` (по умолчанию `gemma4:latest`), `OLLAMA_URL` (по умолчанию `http://localhost:11434`), `HATSHY_DATA` (по умолчанию `./data`), `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` (только если в настройках выбран OpenAI-совместимый API).

## Как проверить (сценарий для жюри)

0. **Мастер настройки** открывается при первом запуске: статус и скачивание моделей, выбор LLM (Ollama или OpenAI API).
1. **Загрузка.** Нажмите «Новое совещание» → «Загрузить файл» и выберите `samples/shala_meeting.mp3` (шала-казахский, 95 с, 4 участника). Можно взять и запись организаторов «Совещание №1.mp3». На экране обработки видны 5 этапов.
2. **Протокол.** Вкладка «Краткая сводка» показывает краткое содержание, решения, повестку с таймкодами и долю речи. Вкладка «Подробная сводка» — развёрнутый отчёт по каждому вопросу встречи. На вкладке «Транскрипт» у каждой реплики есть говорящий, тег языка `RU` / `KZ` / `RU+KZ` и плашка «Поручение»; по клику на таймкод играет аудио. Справа — поручения с ответственным, сроком и уверенностью, их можно подтвердить.
3. **Экспорт.** «Экспорт PDF / DOCX» скачивает протокол; включите «Анонимизировать ФИО», чтобы проверить анонимизацию.
4. **Дашборд.** Раздел «Поручения»: статусы, сроки, нагрузка, доска и список. В карточке поручения есть цитата с таймкодом и кнопка «Открыть в протоколе».
5. **Напоминания (сценарий 2).** «Уведомления» → «Демо: текущая дата», например `2026-10-16`. Появятся «Срок через N дн.» и «Просрочено», а письма — в `data/outbox/`.
6. **Автотесты и оценка качества:**
   ```bash
   .venv/bin/python -m unittest -v                                   # сроки, язык, регистр имён, VAD
   .venv/bin/python scripts/test_export.py                           # экспорт PDF/DOCX, анонимизация
   .venv/bin/python scripts/asr_check.py                             # CER/WER ASR на казахских и шала-записях
   .venv/bin/python scripts/eval.py --api http://localhost:8000 --id 1 --gold eval/gold.json --meeting 1
   ```

## Результаты измерений

Все замеры сделаны на MacBook Pro M1 Pro, 16 ГБ, в день хакатона. Воспроизвести: команды из раздела выше.

**Распознавание речи** (`scripts/asr_check.py`, синтетические записи из `samples/`, нарезка по эталонным границам реплик):

| Язык реплик | CER | WER |
|---|---|---|
| Казахский (KZ) | 0,6% | 3,9% |
| Шала-казахский (RU+KZ) | 0,7% | 6,1% |
| Русский (RU) | 1,7% | 5,0% |

Казахских букв ә ғ қ ң ө ұ ү һ і распознано 226 из 231 (97,8%). Записи синтетические (TTS), на живой речи цифры будут хуже.

**Диаризация** (`scripts/try_diar.py`): число говорящих определено верно на всех 4 записях с известным составом — совещания организаторов №1 и №2 (5 и 5), шала (4), казахская (3). Живая 35-минутная запись созвона обработана за 32 с (найдено 4 голоса; эталона разметки нет).

**Поручения** (`scripts/eval.py`, сопоставление с эталоном):

| Запись | LLM | Найдено из эталона | Ответственный верно | Срок верно |
|---|---|---|---|---|
| Совещание №1 (организаторы) | gpt-5.2 (OpenAI API) | 11/11 (precision 79%) | 10/11 | 11/11 |
| Совещание №2 (организаторы) | gpt-5.2 (OpenAI API) | 8/10 (precision 89%) | 8/8 | 7/8 |
| Шала-казахская (samples) | gemma4 (Ollama, локально) | 4/4 | 4/4 | 4/4 |
| Казахская (samples) | gemma4 (Ollama, локально) | 5/5 | 5/5 | 5/5 |

Эталон для записей организаторов размечен по текстам протоколов, а аудио местами от них отличается (другая область, другие сроки в итоговой реплике председателя), поэтому часть расхождений — это расхождения самого аудио с текстом.

**Время обработки** 4–5-минутного совещания: подготовка аудио, диаризация и распознавание — 12–19 с. LLM через OpenAI API — 35–45 с (плюс ~25 с на подробную сводку). Локальная gemma4 8B — от 4 минут на свободной машине до 10–13 минут, когда память занята другими программами (16 ГБ RAM, модель занимает ~10 ГБ).

**Юнит-тесты:** `python -m unittest` — разбор сроков на русском и казахском, тег языка, регистр имён, VAD.

## Данные и внешние сервисы

- **Записи организаторов** «Совещание №1.mp3» и «Совещание №2.mp3» и эталонные протоколы лежат в папке `spec/`.
  - `eval/gold.json` — эталон из 21 поручения, размеченный вручную по этим протоколам (цитаты дословные, сроки пересчитаны от даты 23.09.2026).
  - Записи отличаются от текстов протоколов: например, в записи №1 звучит «Атырауская область» и есть фраза «следующее совещание через месяц».
- **Казахская и шала-казахская записи** в `samples/` синтезированы голосами macOS TTS (Aru kk_KZ, Milena ru_RU) скриптом `scripts/make_samples.sh`; кейс допускает синтетические записи. Рядом лежат сценарии (`*.script.md`), границы реплик (`*.turns.json`) и эталон поручений (`*.gold.json`).
- **Внешние сервисы во время работы:** по умолчанию нет. Только если в настройках явно выбран OpenAI API, текст транскрипта отправляется туда. Сеть нужна только при установке: PyPI; модели с Hugging Face и GitHub Releases (sherpa-onnx); gemma4 из реестра Ollama.
- **Секретов в репозитории нет.** Ключ OpenAI (если используется) вводится в интерфейсе и хранится только в локальной БД `data/` (в `.gitignore`); `.env` тоже в `.gitignore`.

## Известные ограничения

- **Бота-участника Zoom / Teams / Meet нет.** Звук конференции захватывается через системное аудиоустройство (например, BlackHole) и запись в браузере. Облачные боты вроде Recall.ai противоречат требованию закрытого контура.
- **Live-режим** показывает распознанный текст каждые ~4 с без диаризации. Протокол с говорящими и поручениями строится после «Завершить».
- **Скорость локальной LLM.** На ноутбуке 16 ГБ gemma4 8B обрабатывает совещание минутами (см. измерения). Выход — модель поменьше (qwen2.5:3b/7b через мастер), GPU-сервер (не проверено) или OpenAI-совместимый API.
- **Длинные встречи.** Транскрипт отправляется в LLM целиком (контекст до 32k токенов); разбиение 1–2-часовых встреч на части не реализовано.
- **ASR без пунктуации.** Регистр имён восстанавливается по отчествам (-ович, -овна, -ұлы, -қызы) и словарю частых имён.
- **Казахский и шала-казахский** проверены на синтетических TTS-записях. На живой речи качество не измерялось.
- **Диаризация.** Перекрывающуюся речь не обрабатываем. Короткие реплики («Понял»), вклеенные без паузы в чужую речь, могут остаться за соседним говорящим. На живых записях точность не измерена (нет разметки).
- **Голосовые профили по тембру** не реализованы: эмбеддинги есть, но регистрации образцов нет, в интерфейсе стоит «Нет образца».
- **СЭД:** интеграции нет, кнопка честно сообщает «в разработке».
- **Авторизации и ролей на сервере нет.** Переключатель ролей работает только в интерфейсе.
- **Анонимизация в экспорте** теряет падеж: «свяжитесь с Участник 5».
