# 1. AI Hatshy — ИИ-секретарь совещаний с фиксацией поручений

Решение кейса HackAlem AI «Система автопротоколирования совещаний с фиксацией поручений». «Хатшы» по-казахски — «секретарь».

## 2. Краткое описание

**Проблема.** Протоколы совещаний ведут вручную. Это отнимает время секретаря, а поручения, сроки и ответственные теряются или искажаются, и контролировать исполнение становится трудно.

**Для кого.**
- **Секретарь** записывает совещание и получает готовый протокол.
- **Руководитель** видит поручения, сроки и просрочки на дашборде.
- **Ответственные** получают свои поручения и напоминания.

**Что делает система.** По записи совещания на русском, казахском или смешанном языке (шала-казахский) система строит протокол:
- транскрипт с разделением по говорящим;
- поручения с ответственным и сроком;
- краткую и подробную сводку;
- экспорт в PDF и DOCX.

Дальше она ведёт статусы поручений и напоминает о сроках. Распознавание речи и диаризация всегда работают локально. Языковая модель по умолчанию тоже локальная (Ollama), внешний API включается только явно в настройках.

## 3. Что реализовано

| Функция | Реализация | Код |
|---|---|---|
| Распознавание речи RU / KZ / шала-казахский | Одна модель GigaAM-Multilingual large CTC (int8 ONNX, CPU) с общим словарём RU+KZ. Язык каждой реплики (`RU` / `KZ` / `RU+KZ`) определяется по казахским буквам и служебным словам | `app/pipeline/asr.py`, `app/pipeline/text.py` |
| Диаризация и привязка к людям | Детектор речи Silero VAD → голосовые эмбеддинги NeMo TitaNet-small → агломеративная кластеризация (число голосов подбирается автоматически) → поиск смены говорящего внутри длинных фрагментов. Имена определяются по обращениям («Гульмира Сериковна, вам слово» → следующая реплика её). Говорящего можно переименовать вручную | `app/pipeline/diarize.py`, `app/pipeline/llm/speaker_names.py` |
| Голосовые профили (узнавание по тембру) | В «Участниках» профиль создаётся двумя способами: по фрагменту обработанного совещания или по 20-секундной записи с микрофона. Для фрагмента открывается окно: выбирается совещание, на шкале записи подсвечены реплики человека по диаризации, фрагмент выделяется мышью или кликом по реплике, его можно прослушать, рядом виден текст сказанного. Хранится только усреднённый вектор голоса TitaNet, исходная запись образца удаляется. В новых совещаниях голос каждого говорящего сравнивается с профилями: при сходстве ≥ 0,65 и отрыве от второго кандидата имя подставляется с пометкой «голос». Этот источник имени приоритетнее обращений | `app/voice.py` |
| Поручения с ответственным и сроком | LLM извлекает поручения по JSON-схеме. Затем правила без LLM: цитата-основание должна найтись в транскрипте, срок пересчитывается резолвером от даты совещания («до пятницы», «к среде», «за две недели», «жұмаға дейін», «он бесінші қазанға дейін» → дата), определяются срочность и направление. Непроверенные пункты помечаются «требует проверки». Секретарь подтверждает поручения | `app/pipeline/llm/*`, `app/pipeline/protocol.py` |
| Краткая сводка | Краткое содержание, принятые решения, повестка с таймкодами, ключевые цифры, доля речи участников | `app/pipeline/protocol.py` |
| Подробная сводка | Отдельный отчёт LLM: разбор каждого вопроса (обсуждение, факты и цифры, решения, поручения, риски, открытые вопросы), позиции участников, следующие шаги, вывод | `app/pipeline/report.py` |
| Экспорт PDF / DOCX | Структура эталонных протоколов организаторов: тема, краткое содержание, решения, таблица «Поручение / Ответственный / Срок», стенограмма с таймкодами, участники, подписи. Разделы выбираются, есть анонимизация ФИО | `app/export/*` |
| Уведомление о записи (сценарий 1) | Переключатель «Уведомить участников о записи»: при старте записи проигрывается объявление на казахском и русском (`app/static/consent.mp3`), отметка сохраняется в совещании | `web/index.html` |
| Напоминания (сценарий 2) | Правила «за 3 дня», «в день срока», «ежедневно при просрочке», «эскалация поручившему» (включаются в интерфейсе). Лента уведомлений и письма `.eml` в локальный каталог `data/outbox/`. Для демонстрации можно подставить «текущую дату» | `app/reminders.py` |
| Дашборд поручений | Статусы «В работе / Просрочено / Выполнено», исполнительская дисциплина, сроки на две недели, нагрузка по ответственным, направления, доска и список с фильтрами | `web/index.html` |
| Выдержки ответственным | Каждому ответственному формируется письмо с его поручениями и цитатами, письма сохраняются в `data/outbox/` | `app/reminders.py` |
| Запись в браузере | Микрофон или звук конференции (например, через BlackHole). Куски по 4 с отправляются на сервер, распознанный текст показывается во время записи; протокол строится после «Завершить» | `web/index.html`, `app/pipeline/runner.py` |
| ИИ-помощник («Спросить ИИ») | Чат по совещаниям на любом экране. Вне встречи получает индекс всех совещаний (темы, решения, поручения, участники) и найденные по словам вопроса фрагменты транскриптов. Отвечает кратко и даёт ссылки на совещание и момент записи; по ссылке открывается протокол на нужном таймкоде. Внутри встречи работает в контексте этой встречи (сводки, поручения, транскрипт) | `app/assistant.py` |
| Интеграции (исходящие вебхуки) | В «Настройках» добавляется любое подключение: адрес, метод, авторизация (Bearer-токен или свой заголовок), стандартный JSON или свой шаблон с подстановками `{{title}}`, `{{owner}}`, `{{due}}` и др. Есть проверка подключения. Поручение отправляется кнопкой в карточке или автоматически после формирования протокола; результат пишется в историю поручения | `app/integrations.py` |
| Локальный MCP-сервер | MCP-сервер для ИИ-агентов (Claude Code, Claude Desktop): 9 инструментов, в том числе список и детали совещаний, поиск по стенограммам, поручения и их статусы, загрузка записи, экспорт протокола. Транспорт stdio, обращается только к локальному API. Подробно — [docs/MCP.md](docs/MCP.md) | `app/mcp_server.py`, `scripts/mcp.sh` |
| Выбор LLM | Локальная Ollama (по умолчанию) или OpenAI-совместимый API (OpenAI либо свой сервер, например vLLM), с проверкой подключения | `app/llm_settings.py` |
| Мастер первого запуска | Статус и скачивание моделей распознавания с прогрессом, загрузка моделей Ollama, выбор LLM | `app/setup.py` |
| Мобильная версия | `/m`: главная, запись с микрофона, поручения, уведомления, манифест веб-приложения | `web/mobile.html` |
| Прочее | Переобработка записи, удаление совещания вместе с аудио, светлая и тёмная тема, переключатель RU / KZ / EN для навигации | `app/main.py`, `web/index.html` |

## 4. Как работает решение

1. **Вход.** Секретарь нажимает «Новое совещание» и загружает аудио- или видеофайл (MP3, WAV, M4A, MP4 и другие форматы, которые читает ffmpeg) либо записывает совещание в браузере. При записи участники слышат уведомление.
2. **Обработка** идёт в фоне, по одному совещанию за раз, с прогрессом на экране:
   1. подготовка аудио (ffmpeg → 16 кГц моно);
   2. разделение говорящих;
   3. распознавание речи;
   4. выделение поручений, ответственных и сроков;
   5. формирование сводки и протокола.
3. **Результат.** Открывается страница совещания:
   - **«Краткая сводка» и «Подробная сводка»**;
   - **«Транскрипт»** с говорящими, тегами языка, плеером и переходом по таймкодам;
   - **справа — поручения** с ответственным, сроком, цитатой и уверенностью.
4. **Работа с протоколом.** Секретарь подтверждает поручения, при необходимости переименовывает говорящих, скачивает PDF/DOCX и рассылает выдержки ответственным.
5. **Контроль.** В разделе «Поручения» видны статусы и сроки. Напоминания о приближении срока и просрочке появляются в «Уведомлениях» и в `data/outbox/`.

## 5. Технологии

- **Язык и сервер:** Python 3.12, FastAPI, uvicorn, SQLite, ffmpeg.
- **Распознавание речи:** [GigaAM-Multilingual large CTC](https://huggingface.co/istupakov/gigaam-multilingual-large-ctc-onnx), int8 ONNX, ~592 МБ, лицензия MIT; запускается через `onnx-asr`.
- **Диаризация:** `sherpa-onnx`; Silero VAD (ONNX); NeMo TitaNet-small (ONNX, 38 МБ). Кластеризация, поиск смены говорящего и определение имён по обращениям написаны в проекте.
- **LLM:**
  - по умолчанию gemma4 (8B, Q4_K_M) в Ollama на `localhost:11434`;
  - как вариант — OpenAI-совместимый Chat Completions API со структурированным выводом (JSON Schema);
  - на момент замеров использовалась модель `gpt-5.2`.
- **Экспорт:** `python-docx`; `fpdf2` со шрифтом Montserrat (OFL, есть казахские буквы ә ғ қ ң ө ұ ү һ і).
- **Интерфейс:** HTML-шаблоны дизайн-макета на dc-runtime (`app/static/support.js`) и React 18 UMD. React и шрифты IBM Plex лежат в `app/static/`, страницы не обращаются к CDN.
- **Тестовые данные:** macOS TTS (голоса Aru kk_KZ и Milena ru_RU) и ffmpeg для синтетических записей.

Полный список сторонних компонентов и лицензий — в [THIRD_PARTY.md](THIRD_PARTY.md).

## 6. Архитектура проекта

```
Браузер: веб (/) и мобильный (/m)
  │  REST + загрузка файлов; запись в браузере (MediaRecorder, куски по 4 с)
  ▼
FastAPI  app/main.py ─────────────► SQLite  data/hatshy.db
  │                                  (совещания, реплики, говорящие, поручения, уведомления, настройки)
  ├─ app/pipeline/runner.py  — очередь обработки, одна задача за раз; live-распознавание; сторож брошенных записей
  │    1. audio.py        ffmpeg → 16 кГц
  │    2. diarize.py      Silero VAD → TitaNet → кластеризация → реплики
  │    3. asr.py, text.py GigaAM по каждой реплике, регистр имён, тег языка
  │    4. llm/extract.py  LLM (Ollama или OpenAI-совместимый API) → участники, поручения, саммари (JSON)
  │    5. protocol.py     имена по обращениям, проверка цитат (llm/verifier.py),
  │                       сроки (llm/deadline_resolver.py), срочность, уверенность
  │    6. report.py       подробная сводка (второй вызов LLM)
  ├─ app/reminders.py     правила напоминаний, эскалация, выдержки → data/outbox/*.eml
  ├─ app/export/          PDF (fpdf2) и DOCX (python-docx)
  ├─ app/voice.py         голосовые профили: вектор голоса участника, узнавание говорящих по тембру
  ├─ app/assistant.py     ИИ-помощник: индекс совещаний + поиск фрагментов → LLM → ответ со ссылками
  ├─ app/integrations.py  пользовательские интеграции (HTTP-вебхуки), журнал отправок
  │
  └─ app/mcp_server.py    отдельный процесс (stdio) для ИИ-агентов → REST API на localhost
  ├─ app/setup.py         мастер: статус и скачивание моделей, загрузка моделей в Ollama
  └─ app/llm_settings.py  выбор провайдера LLM; ключ хранится только в data/
```

Ответ LLM не принимается на веру. Цитата поручения сверяется с транскриптом, срок пересчитывается правилами, имя ответственного сверяется с говорящими. Пункт, не прошедший проверку, получает низкую уверенность и метку «требует проверки».

Контракт API и модулей описан в [CONTRACT.md](CONTRACT.md).

## 7. Установка и запуск

Нужно: macOS или Linux, Python 3.12, [uv](https://docs.astral.sh/uv/), ffmpeg, [Ollama](https://ollama.com) (если используется локальная LLM). Проверено на MacBook Pro M1 Pro, 16 ГБ.

```bash
git clone https://github.com/BAITC-Hacks/hack-c9414062-smaguloveka.git
cd hack-c9414062-smaguloveka

# 1. Зависимости Python
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r pyproject.toml

# 2. Модели распознавания и диаризации (~0,63 ГБ, один раз).
#    Шаг можно пропустить: модели скачает «Мастер настройки» при первом открытии интерфейса.
./scripts/download_models.sh

# 3. Локальная LLM (~9,6 ГБ). Можно выбрать другую модель Ollama или OpenAI API в мастере.
ollama pull gemma4

# 4. Сервер
.venv/bin/python -m uvicorn app.main:app --port 8000
```

Откройте http://localhost:8000 (веб) или http://localhost:8000/m (мобильная версия). При первом запуске откроется «Мастер настройки».

Необязательные переменные окружения (см. [.env.example](.env.example)):
- `OLLAMA_URL`, `LLM_MODEL` — локальная LLM;
- `HATSHY_DATA` — каталог данных;
- `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` — нужны, только если выбран OpenAI-совместимый API.

## 8. Как проверить решение

1. **Мастер настройки** откроется при первом запуске. Модели должны стать «✓ Установлено», выберите LLM.
2. **Обработка.** «Новое совещание» → «Загрузить файл» → `samples/shala_meeting.mp3`: шала-казахский, 95 с, 4 участника, 4 поручения в эталоне `samples/shala_meeting.gold.json`. Подойдут и записи организаторов `spec/Совещание №1.mp3`, `spec/Совещание №2.mp3`. На экране обработки видны 5 этапов.
3. **Протокол.** Проверьте три вкладки:
   - «Краткая сводка»;
   - «Подробная сводка»;
   - «Транскрипт»: говорящие с именами, теги `RU` / `KZ` / `RU+KZ`, плашки «Поручение», переход по таймкоду.

   Справа — поручения с ответственным и датой срока. Их можно подтвердить.
4. **Экспорт.** «Экспорт PDF / DOCX». Включите «Анонимизировать ФИО» и проверьте, что имена заменены на «Участник N».
5. **Напоминания (сценарий 2).** «Уведомления» → «Демо: текущая дата», например `2026-10-01`. Появятся «Срок через N дн.» и «Просрочено», а письма — в `data/outbox/`.
6. **ИИ-помощник.** Кнопка «Спросить ИИ» справа внизу. На странице совещаний спросите, например, «Где обсуждали охрану труда и что решили?»: придёт ответ со ссылками на совещания и моменты записи. Откройте протокол и спросите «Кто что должен сделать?»: помощник ответит уже по этой встрече.
7. **Интеграции.** «Настройки» → «Интеграции» → «+ Добавить». Укажите адрес своего сервиса (для проверки подойдёт любой HTTP-приёмник, например локальный) и нажмите «Проверить подключение». Затем откройте поручение → «Отправить в «…»»: в истории поручения появится код ответа.
8. **MCP.** Выполните `claude mcp add ai-hatshy -- <путь к проекту>/scripts/mcp.sh` и попросите Claude, например, «Какие поручения просрочены?». Подробно — [docs/MCP.md](docs/MCP.md).
9. **Автопроверки:**
   ```bash
   .venv/bin/python -m unittest -v              # разбор сроков RU/KZ, тег языка, регистр имён, VAD
   .venv/bin/python scripts/test_export.py      # экспорт PDF/DOCX, анонимизация
   .venv/bin/python scripts/asr_check.py        # CER/WER распознавания на samples/
   .venv/bin/python scripts/try_diar.py samples/*.mp3 spec/*.mp3   # число голосов
   .venv/bin/python scripts/eval.py --api http://localhost:8000 --id <id совещания> --gold samples/shala_meeting.gold.json
   ```

**Результаты, полученные в день хакатона** (подробно — [samples/asr_report.md](samples/asr_report.md), [eval/results.md](eval/results.md)):

- **Распознавание** (синтетические записи, нарезка по эталонным границам реплик):

  | Язык | CER | WER |
  |---|---|---|
  | KZ | 0,6% | 3,9% |
  | RU+KZ | 0,7% | 6,1% |
  | RU | 1,7% | 5,0% |

  Казахских букв распознано 226 из 231.
- **Диаризация:** число голосов определено верно на всех 4 записях с известным составом — 5, 5, 4 и 3.
- **Поручения:**

  | Запись | LLM | Найдено из эталона | Ответственный | Срок |
  |---|---|---|---|---|
  | Совещание №1 (организаторы) | gpt-5.2 | 11/11 (precision 79%) | 10/11 | 11/11 |
  | Совещание №2 (организаторы) | gpt-5.2 | 8/10 (precision 89%) | 8/8 | 7/8 |
  | Шала-казахская | gemma4 | 4/4 | 4/4 | 4/4 |
  | Казахская | gemma4 | 5/5 | 5/5 | 5/5 |

  Эталон для записей организаторов размечен по текстам протоколов, а само аудио местами от них отличается.
- **Время на 1,5–4,5-минутную запись:**
  - аудио, диаризация и распознавание — 12–19 с;
  - LLM через OpenAI API — 35–43 с;
  - локальная gemma4 — 5–10 минут: на ноутбуке с 16 ГБ она конкурировала за память с другими приложениями.

  - GitHub Releases sherpa-onnx — TitaNet;
  - реестр Ollama — модель LLM.
- **Сеть во время работы** по умолчанию не нужна. Внешний сервис используется, только если в «Настройках» выбран OpenAI API: тогда туда уходит текст транскрипта, аудио остаётся на сервере. Интерфейс об этом предупреждает.
- **Интеграции:**
  - письма (выдержки и напоминания) пишутся в локальный `data/outbox/`, SMTP-отправки нет;
  - звук Zoom / Teams / Meet захватывается через системное аудиоустройство;
  - любые внешние системы (СЭД, трекер, Bitrix24, Telegram-бот) подключаются как исходящие HTTP-вебхуки; готовых коннекторов под конкретные продукты нет, формат запроса задаётся шаблоном;
  - локальный MCP-сервер для ИИ-агентов, только localhost.
- **ИИ-помощник и MCP.** Помощник использует ту же LLM, что и обработка. MCP-сервер обращается только к локальному API; текст, который он возвращает, получает модель ИИ-клиента.
- **Секреты:** в репозитории их нет. Ключ OpenAI вводится в интерфейсе и хранится только в локальной базе `data/hatshy.db`; каталог `data/` и `.env` в `.gitignore`.

## 10. Ограничения

- Нет бота-участника Zoom / Teams / Meet, звук конференции захватывается через системное устройство. Облачные боты противоречат требованию закрытого контура.
- В live-режиме во время записи показывается только текст без разделения по говорящим. Говорящие и поручения появляются после «Завершить».
- Качество на казахском и шала-казахском измерено только на синтетических TTS-записях. На живой речи и на живых записях диаризация по точности не измерялась, разметки нет.
- Порог узнавания по голосу (0,65) подобран на тестовых записях. На живых записях он не проверялся. Если профиль записан в одном акустическом окружении, а совещание проходит в другом, сходство может упасть ниже порога, и тогда имя определяется по обращениям.
- Перекрывающаяся речь не обрабатывается. Короткие реплики («Понял»), вклеенные в чужую речь без паузы, могут остаться за соседним говорящим.
- ASR не расставляет пунктуацию. Регистр имён восстанавливается эвристически, по отчествам и словарю частых имён.
- Транскрипт отправляется в LLM целиком, до 32k токенов контекста. Разбиение длинных (1–2 ч) встреч на части не реализовано.
- Локальная LLM на ноутбуке с 16 ГБ работает минутами. Ускорить можно меньшей моделью Ollama, GPU-сервером (не проверено) или OpenAI-совместимым API.
- Не реализовано:
  - готовые коннекторы под конкретные СЭД/трекеры (есть универсальные вебхуки) и SMTP;
  - авторизация и роли на сервере — переключатель ролей работает только в интерфейсе.
- Переключатель KZ / EN переводит только названия разделов навигации.
- Анонимизация в экспорте теряет падеж имени: «свяжитесь с Участник 5».
- Мобильная версия проверялась меньше веб-версии. Запись с микрофона на телефоне требует HTTPS или localhost.
